
# 로그인 실행 프롬프트 (2단계용)
AUTH_LOGIN.md와 나란히 놓고 사용합니다.

전제: BOOTSTRAP_PROMPTS.md 1단계 완료. 특히 AuthContext가 이미 만들어져 있어야 합니다(BOOTSTRAP.md 7.3장). 이 문서는 전달 수단, AUTH_LOGIN.md가 내용입니다.

규모: 원본 약 220줄 · 난이도 ★ · 체크리스트 19항목 데모에서 심사위원이 가장 먼저 보는 화면입니다. 작지만 첫인상을 좌우합니다.



## 0. 세션 시작 시 한 번
지금부터 docs/specs/AUTH_LOGIN.md 를 보고 "로그인" 화면을 만든다.

## 1. 기본 — 스펙을 통째로
화면이 작아 한 번에 시켜도 충분합니다.

docs/specs/AUTH_LOGIN.md 를 처음부터 끝까지 읽고 로그인 화면을 만들어줘.
src/app/(auth)/login/page.tsx 에 만든다. 이 화면은 사이드바도 PageHeader도 쓰지 않는다.

범위:
- 4장 화면 구성 (좌 히어로 패널 / 우 로그인 폼)
- 5장 로직 (슬라이드쇼 · 카운트업 · 절감량 집계 · 로그인 · 데모 계정 자동 입력)

카운트업 레이아웃 흔들림 방어 3종을 반드시 함께 적용해라. 하나라도 빠지면 숫자가 올라갈 때
카드가 떨린다:
  ① 히어로 콘텐츠 블록에 w-[36rem] 고정 폭
  ② 값에 formatTonFixed (소수 자릿수 고정) — formatTon을 쓰지 마라
  ③ 값 텍스트에 tabular-nums whitespace-nowrap

슬라이드쇼는 이미지 5장을 모두 렌더링해두고 opacity만 전환한다.
DOM에서 넣고 빼면 크로스페이드가 끊기고 전환마다 재로드된다.

다 만들면 9장 재구현 체크리스트로 누락을 확인해줘.

완료 확인 — 좌측 배경이 6초마다 부드럽게 바뀌고, 통계 숫자가 0에서 올라가는 동안 카드 폭이 흔들리지 않는다. 데모 계정 버튼을 누르면 이메일·비밀번호가 자동으로 채워진다.



## 2. 완료 검증
docs/specs/AUTH_LOGIN.md 9장 재구현 체크리스트 19항목을 확인해줘.
그다음 8장 엣지 케이스 15개를 훑어보고 위반한 것이 있는지 점검해줘.

특히 아래를 확인해줘:
- 브라우저 콘솔에 hydration 경고가 없는지
- 1024px 미만으로 줄였을 때 좌측 패널이 사라지고 우측 상단에 로고가 나타나는지
- client1@shipping.co.kr 로 로그인했을 때 사이드바 메뉴가 1개만 보이는지

마지막 항목이 통과하면 RBAC가 실제로 동작하는 것입니다. 데모에서 보여주기 좋은 장면입니다.
