## 1. React / Next.js

### 1.1 하이드레이션 불일치 — localStorage를 초기값으로 읽음
증상: 콘솔에 Hydration failed because the server rendered HTML didn't match the client, 첫 렌더에서 테마·사이드바·로그인 상태가 순간 깜빡임. 원본에서는 (main)/layout.tsx와 로그인 화면에서 두 번(#133, #160) 발생했다 — 한 번 고쳤다가 롤백으로 유실되어 재발했다.

원인: useState의 지연 초기화 함수에서 localStorage를 읽었다. 서버에는 localStorage가 없어 서버 렌더 결과와 클라이언트 첫 렌더 결과가 달라진다.

해결: 대상에 따라 두 가지 패턴을 쓴다.


| 대상 | 패턴 |
| --- | --- |
| 테마, 사이드바 접힘 등 단순 값 | 서버와 같은 기본값으로 시작하고 useEffect에서 1회 동기화 |
| 로그인 상태처럼 외부 저장소를 구독해야 하는 값 | useSyncExternalStore + getServerSnapshot(항상 null 반환) |


재발 방지: 롤백·머지 후에는 이 세 파일(ThemeContext·Sidebar·AuthContext)이 여전히 올바른 패턴인지 확인한다. 실제로 롤백 한 번에 되살아난 버그다.

관련: PROMPTS #133, #160 / BOOTSTRAP.md 7.1·7.3장

### 1.2 useSyncExternalStore 무한 리렌더
증상: The result of getSnapshot should be cached to avoid an infinite loop 경고와 함께 렌더가 멈추지 않음.

원인: getSnapshot이 매 호출마다 JSON.parse(...)로 새 객체를 반환. React는 참조가 다르면 값이 바뀐 것으로 판단한다.

해결: 모듈 스코프에 원본 문자열과 파싱 결과를 캐시하고, 문자열이 그대로면 이전 객체를 재사용한다.

let cachedRaw = null, cachedUser = null
getSnapshot():
  raw = localStorage.getItem(KEY)
  if (raw !== cachedRaw) { cachedRaw = raw; cachedUser = raw ? JSON.parse(raw) : null }
  return cachedUser

### 1.3 setState 함수형 업데이터 안에서 다른 setter 호출
증상: 필터 버튼("My")이 간헐적으로 동작하지 않음. 눌러도 아무 반응이 없다가 가끔 되기도 함. 원본에서 이 하나를 잡는 데 3라운드(#237·#238·#239)를 썼다.

원인: setActiveFilters(prev => { ... }) 업데이터 내부에서 setSelectedVoyageIds·setGaugesOpen 같은 다른 state의 setter를 호출했다. React는 업데이터 함수를 여러 번 재실행할 수 있으므로 (StrictMode·동시성 렌더링) 부수효과가 중복 실행된다.

해결: 업데이터는 순수하게 유지한다. 판단에 필요한 값은 업데이터 바깥에서 먼저 읽고, 다른 setter도 바깥에서 한 번만 호출한다.

- setFilters(prev => { const wasActive = prev.has(k); setOther(...); return next })
+ const wasActive = filters.has(k)
+ setFilters(prev => next)
+ if (wasActive) setOther(...)

관련: PROMPTS #237~#239

### 1.4 펼침 상태 반영 전에 스크롤 위치를 계산
증상: 다른 화면에서 딥링크로 넘어왔을 때, 대상 카드가 화면 최상단에 정확히 맞지 않고 어긋남.

원인: 목록이 "첫 항목 펼침" 상태로 시작하는데, 대상 카드를 펼치는 setState 이전 레이아웃 기준으로 스크롤 위치가 계산됐다.

해결: flushSync로 펼침 상태를 동기 커밋한 뒤 스크롤한다.

관련: PROMPTS #193

### 1.5 Next.js Dev Indicator는 조건부로 숨길 수 없다
증상: 화면 좌하단에 정체불명의 원형 N 배지가 뜸(클릭하면 Route/Bundler 정보 표시). "관리자에게만 보이게 해달라"는 요구가 나왔으나 불가능하다.

원인: 프레임워크가 개발 모드에 주입하는 오버레이라 애플리케이션 로그인 상태와 무관하다.

해결: next.config.ts에 devIndicators: false로 전체 비활성화하는 것만 가능하다.

관련: PROMPTS #199 / BOOTSTRAP.md 3.1장

### 1.6 CI 린트 4건
로컬에서는 통과하는데 CI에서 막힌 항목들이다.


| 파일 | 문제 | 해결 |

## 2. 지도 (Leaflet)
대시보드를 구현하지 않는다면 이 장 전체를 건너뛴다.

### 2.1 Leaflet divIcon 텍스트 클리핑
증상: 지도 위 카드형 마커에서 하단 텍스트가 잘려 보임.

원인: iconSize를 지정하지 않고 iconAnchor만 준 경우, Leaflet이 0×0 컨테이너를 만들어 내부 콘텐츠를 잘라낸다.

해결: 아래 조합을 정석 패턴으로 쓴다.

iconSize: [0, 0]
iconAnchor: [0, 0]
+ CSS: transform: translate(-50%, -50%)      /* 실제 중앙 정렬은 CSS로 */

관련: PROMPTS #18

### 2.2 마커 겹침 — pane 분리
증상: 기상 정보 카드가 선박 마커를 가려서 배가 안 보임.

해결: Leaflet 커스텀 pane으로 z축을 분리한다.


| pane | z-index | 용도 |
| --- | --- | --- |
| weatherPane(신규) | 400 | 기상 카드 — pointer-events: none으로 클릭 투과 |
| markerPane(기본) | 600 | 선박 마커 — 항상 위 |


배경 카드는 반투명(rgba(248,250,252,0.48))으로 낮추고 테두리·그림자도 연하게 한다.

관련: PROMPTS #29

### 2.3 maxBounds에 위도 ±90을 쓰면 투영이 발산한다
증상: 지도가 잘려 보이거나 과도하게 축소됨.

원인: Web Mercator 투영은 위도 ±90°에서 무한대로 발산한다.

해결: 안전 한계인 ±85.0511° 를 쓴다. 최소 줌 계산도 위도까지 함께 맞추지 말고 가로 폭 기준으로만 단순화한다.

관련: PROMPTS #164

### 2.4 TileLayer.bounds가 랩핑 좌표를 재정규화해 타일이 안 뜸
증상: 태평양 등 특정 해역만 회색으로 표시됨.

원인: TileLayer의 bounds 옵션이 날짜변경선을 넘어 랩핑된 타일 좌표를 표준 -180~180으로 재정규화해, 이동된 이음매 범위와 어긋나 타일 요청이 누락됐다.

해결: 타일 레이어의 bounds를 제거하고 map.maxBounds만으로 범위를 제어한다.

관련: PROMPTS #165

### 2.5 오류를 200 응답 이미지로 반환하는 타일 서버
증상: 확대하면 타일에 Zoom Level not supported 문구가 그림으로 보임. errorTileUrl 폴백을 걸어도 소용없음. 원본에서 3라운드(#226·#227·#228) 소요.

원인: OpenSeaMap 해도·RainViewer 레이더 서버는 지원 범위를 벗어난 줌에서 HTTP 오류가 아니라 오류 문구가 그려진 정상 이미지를 200으로 반환한다. errorTileUrl은 이미지 로드 실패 시에만 동작하므로 걸러지지 않는다.

해결: 레이어별로 maxZoom을 고정해 요청 자체를 막는다.


| 레이어 | maxZoom |
| --- | --- |
| OpenSeaMap 해도 | 12 |
| RainViewer 레이더 | 10 |
| 지도 전체 | 15 |
| 기본지도·위성 | maxNativeZoom 지정(없는 고줌 타일 요청 억제) |


관련: PROMPTS #226~#228

### 2.6 CSS 애니메이션 transform이 Leaflet 위치 transform과 충돌
증상: 깜빡임 효과를 준 위험 마커가 엉뚱한 위치에 표시됨.

원인: Leaflet은 마커 위치 이동에 래퍼 div의 transform: translate3d를 쓴다. 같은 요소에 애니메이션용 transform을 걸면 서로 덮어쓴다.

해결: 애니메이션 클래스를 래퍼가 아니라 html 내부의 자식 div에 적용한다.

관련: PROMPTS #211

### 2.7 flyTo의 곡선 궤적이 큰 화면에서 두 동작으로 보임
증상: 필터 클릭 시 지도가 "제자리에서 줌아웃 → 그 다음 이동"처럼 끊겨 보임.

원인: map.flyTo의 swoop(곡선) 궤적은 화면이 클수록 두 단계로 두드러진다.

해결: 이동 성격에 따라 분기한다.


| 동작 | 메서드 |
| --- | --- |
| 필터 리셋(줌 델타가 큼) | map.setView({ animate: true }) — 팬+줌을 하나의 전환으로 |
| 이슈·항구·선박 위치로 이동 | flyTo 유지 |


추가로 지도 생성 옵션에 zoomAnimationThreshold: 20 을 준다. 기본값 4로는 줌 델타가 큰 리셋이 애니메이션 없이 순간 이동해 버린다.

관련: PROMPTS #262

### 2.8 지도 오버레이 버튼 클릭이 부모 패널 토글까지 발동
증상: 지도 위 레이어 토글 버튼을 눌렀는데 패널 전체가 접힘.

해결: 버튼·토글 행의 클릭 핸들러에 stopPropagation()을 추가해, 여백을 눌렀을 때만 접히게 한다.

관련: PROMPTS #221

### 2.9 두 항구를 직선 보간하면 항로가 육지를 지난다
증상: 항로선과 선박 마커가 대륙을 가로지름(말레이시아·보르네오·필리핀 등). 자사 항차(#27)와 타사 항차(#92) 양쪽에서 각각 발생했다.

원인: 출발·도착 위경도를 단순 선형 보간했다.

해결: 사전 계산된 실해상 항로 폴리라인을 쓴다.

항로선: routes.json의 폴리라인 그대로
실제 이동 경로(actualRoute): 전체 항로를 현재 AIS 위치에 가장 가까운 포인트까지 슬라이스
타사 선박 위치: 폴리라인을 누적거리 기준으로 보간(pointAtFraction) — 단순 인덱스 비례는 웨이포인트 간격이 불균일해 어긋난다

항로 데이터를 만들 시간이 없으면 SCHEDULE.md 6.3장의 haversine × 1.25 폴백을 쓴다. 육지 회피는 못 하지만 거리·ETA는 그럴듯해진다.

관련: PROMPTS #27, #92



## 3. 날짜·시각

### 3.1 UTC ISO 문자열을 slice로 자르면 로컬 시각과 어긋난다
증상: 목록 화면과 상세 팝업의 시·분이 다르게 표시됨.

원인: 목록은 toLocaleString(로컬 타임존 변환)으로 표시하는데, 팝업은 iso.slice(0,16)으로 UTC 문자열을 그대로 잘라 썼다. 타임존 오프셋만큼 어긋난다.

해결: Date의 로컬 getter로 재구성한다.

isoToLocal(iso):
  d = new Date(iso)
  return `${d.getFullYear()}-${pad(d.getMonth()+1)}-${pad(d.getDate())}T${pad(d.getHours())}:${pad(d.getMinutes())}`

관련: PROMPTS #134 / SCHEDULE.md 5.6장

### 3.2 날짜 미선택 상태에서 시·분 변경이 저장되지 않음
증상: 날짜를 고르기 전에 시·분·오전오후를 먼저 바꾸면 선택이 조용히 사라짐.

원인: 날짜·시·분을 합치는 함수가 날짜가 비었을 때 ''를 반환해 값이 통째로 버려졌다.

해결: 날짜 미선택 시 오늘 날짜를 기본값으로 채워 항상 완전한 값을 만든다.

관련: PROMPTS #131 / SCHEDULE.md 5.6장

### 3.3 좁은 select에서 네이티브 화살표가 텍스트를 밀어냄
증상: 오전/오후 드롭다운의 선택된 글자가 안 보임.

해결: appearance-none으로 네이티브 화살표를 제거하고 최소 폭(min-w-[56px])을 지정한다.

관련: PROMPTS #131



## 4. 레이아웃·타이포

### 4.1 카운트업 애니메이션 중 너비가 매 프레임 재계산됨
증상: 숫자가 올라가는 동안 카드 너비와 배경 레이어가 계속 흔들림.

원인: 값의 소수 자릿수가 프레임마다 달라지고(3.5 → 12.75 → 128.1), grid 컬럼 너비가 그때마다 다시 계산됐다.

해결: 세 가지를 함께 적용한다.

소수 자릿수 고정 — formatTonFixed(n, 1)처럼 minimumFractionDigits까지 지정
컨테이너 고정 너비 — 히어로/통계 블록에 w-[36rem] 등
값 텍스트에 whitespace-nowrap

관련: PROMPTS #254 / BOOTSTRAP.md 8.5장

### 4.2 큰 숫자(소수점 포함) 텍스트가 카드 폭을 초과
증상: 3,559.5 ton 같은 값이 카드 우측 경계를 넘어감. 원본에서 두 번(#244·#255) 발생.

해결: 폰트 크기·패딩·grid gap을 함께 조정하고 overflow-hidden을 보강한다. 고정폭 대신 minmax(0, 1fr) 기반 반응형 그리드를 쓰면 저해상도에서도 안전하다.

관련: PROMPTS #244, #255, #262

### 4.3 overflow-y-auto만 지정하면 overflow-x도 auto가 된다
증상: 사이드바를 접었을 때 하단에 불필요한 가로 스크롤바가 생김.

원인: 접힘 상태의 hover 툴팁(absolute left-full)이 opacity-0이어도 레이아웃 공간을 차지해 스크롤 가능 영역을 넓혔다. 그리고 CSS 스펙상 한 축에 auto를 주면 다른 축도 암묵적으로 auto 가 된다.

해결: overflow-x-hidden을 명시한다.

관련: PROMPTS #199 / BOOTSTRAP.md 8.2장

### 4.4 음수 마진으로 붙인 문구가 줄바꿈되면 겹친다
증상: RTA 지연 경고 문구가 아래 ETA 박스를 침범.

원인: 그리드 하단에 -mb-2 음수 마진으로 붙여둬, 문구가 2줄이 되면 겹쳤다.

해결: 음수 마진 대신 해당 입력 필드에 종속된 인라인 메시지로 위치를 옮긴다.

관련: PROMPTS #177 / SCHEDULE.md 5.8장

### 4.5 부동소수점 연산 오차가 그대로 렌더링됨
증상: 화면에 364.29999999999995 같은 값이 노출됨.

해결: 계산 결과를 렌더링하는 모든 지점에 toFixed(n)을 적용한다. 특히 뺄셈·나눗셈으로 파생된 "절감량·차이" 값이 위험하다.



## 5. 데이터 정합성 (mock)
mock 데이터는 "그럴듯해 보이지만 물리적으로 앞뒤가 안 맞는" 상태가 되기 쉽다. 아래 4건은 모두 화면 버그가 아니라 데이터 버그였다.

### 5.1 AIS 위치가 항로와 무관하게 작성되어 있었음
증상: 선박 마커가 항로선에서 한참 벗어난 엉뚱한 바다에 떠 있음.

원인: 위치 좌표를 손으로 적당히 찍었다.

해결: ETD + 경과 시간 + 속도로 항로상의 진행률을 구하고, 그 지점의 웨이포인트 좌표를 쓴다. COG(침로)도 인접 웨이포인트의 방위각으로 재계산한다.


| 선박 | 수정 전 | 수정 후 (진행률) |
| --- | --- | --- |
| v001 | 홍해 25°N, 38°E | 싱가포르 해협 1.1°N, 103.6°E (24.2%) |
| v002 | 북태평양 40°N, 155°E | 일본 동방 41.3°N, 139.7°E (18.2%) |
| v003 | 남중국해 10°N, 118°E | 포트헤들랜드 북방 -19.6°N, 118.6°E (2.2%) |
| v004 | 인도양 0°N, 75°E | 스리랑카 남서방 9.7°N, 75.3°E (29.4%) |


관련: PROMPTS #29

### 5.2 같은 지표를 화면마다 다른 공식으로 계산
증상: "현재 13.5kts → 권장 13.5kts"인데 RTA 준수 확률이 90% 로 표시됨. 속도가 같으면 결과도 같아야 하는데 다르다.

원인: 화면마다 확률·연료절감 공식을 따로 구현했다.

해결: 순수 함수 하나로 통일하고 모든 화면이 그것만 호출한다. 원본은 다음 원칙으로 정리했다.

권장 속도든 현재 속도든 동일한 marginToProbability() 하나만 사용(권장 속도라고 100%를 하드코딩하지 않는다)
연료 절감은 일정 마진과 완전히 분리해, 속도 변경으로 인한 실제 연료 소모 차이로만 계산

관련: PROMPTS #95 / AI_REPORT_REQUIREMENTS.md 6장, SCHEDULE.md 6.1장

### 5.3 시뮬레이션 결과 등급이 원본 데이터와 불일치
증상: "현재 속도 유지 시 D등급"인데 기존 데이터 기준으로는 C가 나와야 함.

해결: 등급 산출을 원본 데이터와 정합화하고, 성격이 다른 값(컴플라이언스 문구용 "회피한 등급")은 별도 필드로 분리했다. 하나의 값에 두 가지 의미를 담지 않는다.

관련: PROMPTS #107

### 5.4 신규 항차의 실거리 미계산 / STA·RTA·ETA 중복
증상: 화면에서 등록한 항차만 거리가 0으로 표시되고, 세 시각이 전부 같은 값.

해결: SCHEDULE.md 5.12장의 제출 규칙대로 처리한다.

실거리는 항구쌍 항로 조회로 채우고, 못 구하면 ETA를 RTA로 대체
빈 STA는 RTA로 대체해 저장(항상 값이 있도록)

관련: PROMPTS #126



## 6. 외부 API

### 6.1 XML 속성명 단·복수 차이로 파싱 실패
증상: 실시간 태풍이 화면에 하나도 안 나옴.

원인: GDACS RSS의 심각도 속성이 units=(복수)가 아니라 unit=(단수) 였다. 그리고 값이 텍스트 노드가 아니라 value="..." 속성에 들어 있었다.

해결: 속성명을 정확히 맞추고 값 추출 방식을 attribute 기반으로 수정.

교훈: 외부 XML/JSON은 추측하지 말고 원본 응답을 한 번 찍어서 확인한다. 이 한 글자로 기능 전체가 죽어 있었다.

관련: PROMPTS #41

### 6.2 실데이터가 기본 뷰포트 밖에 있어 안 보임
증상: 파싱을 고쳤는데도 마커가 여전히 안 보임.

원인: 실제 태풍이 동태평양(lng ≈ -122°) 에 있었는데 기본 뷰포트는 서태평양이었다. 데이터는 정상이고 화면 밖에 있었을 뿐이다.

해결: 데모 목적상 mock을 병합해 서태평양에도 표시되도록 보완.

교훈: "데이터가 안 보인다"를 파싱 오류로만 의심하지 말 것. 뷰포트·필터·줌 범위를 먼저 확인하는 게 빠르다.

관련: PROMPTS #42

## 8. 협업·요구사항 (프로세스)
기술 버그는 아니지만 실제로 가장 많은 라운드를 소모한 유형이다. 해커톤처럼 시간이 촉박할 때 치명적이므로 별도로 남긴다.

### 8.1 용어를 반대로 이해한 채 3라운드 소모
경과: "선박상태 기본값을 unfold로 해줘"(#214) → 코드는 이미 그 상태 → 같은 요청 반복(#215) → 확인 질문 → "fold와 unfold를 헷갈렸다"(#216). 실제 의도는 정반대였다.

교훈:

UI 상태 용어를 팀에서 먼저 합의한다(fold=접힘 / unfold=펼침).
"이미 그렇게 되어 있는데요"라는 답이 나오면, 같은 요청을 반복하지 말고 화면 스크린샷으로 현재 상태와 원하는 상태를 확인한다.

### 8.2 토글 요구사항을 쪼개서 요청해 3라운드 소모
경과: "fold면 unfold로 바뀌게"(#237) → "unfold면 fold로도"(#238) → 두 수정이 겹쳐 필터링 기능 자체가 깨짐(#239). 최종 정답은 단순한 v => !v 였다.

교훈:

토글은 방향별로 쪼개서 요청하지 말고 "완전한 토글"로 한 번에 정의한다.
수정 후에는 원래 되던 기능이 여전히 되는지 함께 확인한다(#239가 정확히 이 회귀였다).

### 8.3 이미지 첨부가 가장 빠른 소통 수단
원본에서 화면 관련 버그 신고 상당수가 스크린샷과 함께였고(#18·#27·#29·#46 등), 그 경우 대부분 1라운드에 해결됐다. 반대로 텍스트로만 설명한 레이아웃 문제는 2~3라운드가 걸렸다.

교훈: 화면 문제는 말로 설명하지 말고 캡처를 붙인다.
